# 技术方案报告格式

采用“背景 → 需求 → 整体架构 → 分端及功能设计 → 交付安排”的主线，以短段落、映射表、图示和核心伪代码组织内容。模板适用于不同项目，不预设模块名、技术选型、优先级和业务约束。

## 使用方式

通常以 `[项目][端或模块] Tech Design - 主题` 命名，也可沿用用户指定标题。默认保留背景、需求、技术方案、影响与验收、任务拆分；其余章节有内容再写。不适用章节直接省略并连续编号，不逐章填写“无”“不涉及”。用户要求完整评审模板时保留全部章节，未形成的评审结论写“待评审”。

单端项目不增加空的跨端层级；多端项目先定义共享协议，再分端描述差异。新文档一般使用三级以内标题，复杂功能确有必要时再细分。

## 1. 背景介绍

用一小段说明当前问题与目标。有 PRD、Figma、任务或关联方案时，列 `资料 | 链接 / 作用` 短表；没有来源的行不补占位。

## 2. 需求概述

先用一句话交代本期交付，再按 `需求 / 优先级 | 本期范围 | 依赖 / 验收结果` 列表。优先级沿用输入，不自行把功能定为 P0。后续阶段集中用一行或一小段说明。

## 3. 技术方案设计

### 3.1 整体架构设计

先写采用的架构及主要变化，然后放整体架构图。图后按需列 `模块 | 职责 / 接口 | 关键依赖` 或 `设计选择 | 具体实现 | 原因 / 代价` 表。只写影响本方案的选择，不列通用原则。

跨模块共享的数据模型、事件或接口在这里定义一次。改造已有系统时，简述现状到目标的变化及实际需要的兼容方式；具体调用方影响归“改动影响范围”章节。

### 3.2 端或子系统

单端项目可直接使用功能名称；多端项目在这一层按端划分。按功能组织设计，而不是先堆一整章接口、再堆一整章流程，让读者来回查找。

每项核心功能采用下面的轻量结构，不必为每个标签再建一层标题：

- **行为与入口**：输入、触发及结果。
- **实现**：改动模块、关键接口和分支；必要时附少量字段或状态表。
- **时序图**：关键过程放在对应功能下，共享流程直接引用。
- **核心伪代码**：展示本功能的算法、状态转换或调度决策。
- **验收**：就地给出少量可观察结果，或指向“改动影响范围”章节对应场景。

SDK 升级、资源替换等以配置为主的改动，展示核心配置差异及实际受影响的加载、选择或生效逻辑；不要人为编造并不存在的运行算法。

## 4. 埋点方案

有新增观测需求时，列 `事件 / 指标 | 触发时机 | 关键字段 / 计算口径`。共享字段只列一次；指标需说明统计对象或分母，避免把提交成功直接当作最终业务成功。事件名尚未注册时标为建议名称。

## 5. 质量保障与发布计划

仅写与本次改动相关的具体安排，小项目可以合为一张短表：

- **监控和报警**：指标、判断依据和触发后的动作。没有基线时集中列为待确认，不捏造阈值。
- **灰度方案**：放量对象、开关读取时机、推进条件。比例及观察窗无来源时写建议或待确认。
- **回滚方案**：实际回退动作、生效时点和恢复检查。区分运行配置与需要重新发版的改动。

这里写发布操作，不重复“技术方案设计”章节已有的兼容与失败处理机制。

## 6. 改动影响范围

用 `模块 / 调用方 | 当前行为 | 改动 / 迁移方式` 表记录真实影响。来源能定位代码时附路径或符号；未读取代码时不编造文件名和行号。

验收较多时集中列 `场景 | 预期行为 | 验证方式 / 当前状态`。优先覆盖本次引入的行为变化和关键失败路径，不铺无关测试清单。方案自检与构建、设备、线上验证分开记述，不把计划写成已通过。

## 7. 实验设计

仅在有实验需求时列 `实验 | 对照 / 实验组差异 | 指标与判定方式`。这一节说明要验证的假设；放量操作引用“质量保障与发布计划”章节。

## 8. 方案关键点确认

只收集尚未解决且影响交付的决策：`事项 | 建议 / 待确认内容 | 影响 / 对接角色`。已决定且在正文解释过的内容不重新列一遍。

## 9. 任务拆分和排期

使用 `任务 | 改动与交付物 | 前置依赖 | 负责人 / 估时 / 日期`。没有负责人和日期时只列依赖与交付物，或统一注明待排期；用户要求估算时说明估算依据。代码改动位置可合并进任务表，不重复复制“改动影响范围”章节。

## 10. 参考文档

只列实际使用过的材料和用途。正文已有足够的就地链接时可省略，不重复罗列同一来源。

## 11. 技术方案质量度自评

默认作为内部自检，不占正文。用户或评审模板明确要求时，只列真实缺口和补齐动作；不重复总结各章，不虚构分数或“全部通过”。

## 12. 评审结论

仅记录已有的评审决定、时间和待办；尚未评审时按需写“待评审”，不生成“已通过”或代替评审者投票。
